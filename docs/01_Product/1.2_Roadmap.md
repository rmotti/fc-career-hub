# 1.2 Roadmap

This roadmap is a directional read of the codebase — what the architecture is set up to grow into next — rather than a committed delivery plan. Update it when priorities shift.

## Horizon 1 — Consolidation

Make what exists more reliable, more discoverable, and more complete around the edges.

- **Wire missing API clients**: add `shortlistApi`, `savedSearchesApi`, `scoutingApi` to `shared/api/client.ts` and rebuild the relevant Scout sections on top of them.
- **Persisted lineup**: store the field formation per save so the user's planning survives a refresh.
- **Test coverage of critical flows**: auth, save lifecycle, transfer auto-link, season advance.
- **Toast consolidation**: remove the legacy shadcn Toaster, standardize on Sonner.
- **Environment hardening**: fail loudly when `VITE_API_URL` is missing; drop the legacy Vercel default.
- **Per-feature mini-tours**: extend the tutorial to onboard specific features on first use.

Outcome: a tighter, more trustworthy product without changing what it does.

## Horizon 2 — Depth

Push the product from "tracker" into "career intelligence."

- **Historical analytics**: balance over seasons, OVR trajectory, scoring trends, club-by-club summaries.
- **Compare playbooks live**: side-by-side scoring of a candidate under multiple playbooks.
- **Shortlist enhancements**: notes, priorities, side-by-side compare, share to chat.
- **Streaming chat responses**: switch the Mister assistant to streaming via the Responses API.
- **Save snapshots / export**: JSON backup before season advance; export full save history as a shareable page.
- **Auto-fill from FC26 dataset**: when creating a player manually, look them up by name.

Outcome: the app becomes the source of truth for what happened in a career, not just a log of it.

## Horizon 3 — Reach

Make the product useful outside the desktop tab.

- **Mobile-first views**: optimize Squad, Transfers, and Dashboard for touch.
- **Offline / read-only PWA**: a save remains browsable without connectivity.
- **Server-side chat history**: roam between devices without losing context.
- **Sharing surfaces**: publish a "career page" — a shareable, read-only portrait of a save.
- **Achievements**: derived milestones (first European cup, X clubs managed, longest season streak).

Outcome: the product follows the user, doesn't hold them to one device.

## Investment Criteria

For each candidate item, evaluate against:

1. **Does it deepen retention of the existing user?** (favors Horizon 2)
2. **Does it lower the cost of onboarding a new user?** (favors Horizon 1)
3. **Does it open distribution?** (favors Horizon 3)
4. **Is the technical lift proportionate to the upside?** (favors items that reuse existing API surface)

## Non-Goals (won't do)

- Multiplayer or competitive features.
- Real-world data integration (live FIFA stats, real injuries, live transfers).
- Match simulation.
- Light theme / theme switcher.
- Native mobile apps before a strong PWA exists.

## Auto-audit

- Items chosen because each maps to an explicit gap in the current code (debt list, missing client wrappers, no lineup persistence) or an obvious extension of an already-shipped capability.
- This is a planning document; treat it as a snapshot, not a contract.
