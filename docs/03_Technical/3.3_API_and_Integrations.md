# 3.3 API and Integrations

## Overview

The frontend talks to a single backend: **fc26-career-hub-api** (Fastify + Prisma + Postgres + Redis), mirrored under [`docs/career-hub-api/`](../career-hub-api/) for reference. The HTTP surface is fully captured by the typed objects in [`src/shared/api/client.ts`](../../src/shared/api/client.ts).

Production OpenAPI docs (Swagger UI) are served by the API at `<api-base>/docs`. Use them as the live source of truth for request/response shapes when in doubt.

## Transport

### Base URL
Resolved in `shared/api/client.ts`:

1. `import.meta.env.NEXT_PUBLIC_API_URL` if set.
2. Else `import.meta.env.VITE_API_URL`.
3. Else `https://career-hub-api.vercel.app` (legacy default — production actually runs on Railway).
4. `/api` is appended if missing.

### Headers
- `Content-Type: application/json`.
- `Authorization: Bearer <token>` when `localStorage["session_token"]` is set.

### Status handling
- `204` → resolves with `undefined`.
- `401` (on any path other than `/auth/sign-in`, `/auth/sign-up`) → calls `unauthorizedHandler()` which clears the session.
- `429` → captures `Retry-After` header into `ApiError.retryAfter`.
- Other non-OK → throws `ApiError`.

### Error contract
Backend responses on failure follow one of two shapes:

```json
{ "error": "Erro interno do servidor.", "statusCode": 500 }
{ "error": "SHIRT_NUMBER_CONFLICT", "message": "Camisa 10 já está em uso", "statusCode": 409 }
```

The frontend `ApiError` carries `{ message, status, data, isNetworkError, retryAfter }`. Use `extractErrorMessage(err)` from `shared/api/client.ts` to compute the user-facing string — it knows about specific codes like `SHIRT_NUMBER_CONFLICT`.

## Endpoints

All endpoints below are prefixed with `/api`. Auth endpoints are public; everything else requires a valid session token.

### Auth — `authApi`
| Method | Path | Notes |
|---|---|---|
| `POST` | `/auth/sign-up/email` | Body `{ name, email, password, plan? }`. Returns `{ token, user }`. |
| `POST` | `/auth/sign-in/email` | Body `{ email, password }`. Returns `{ token, user }`. |
| `GET` | `/auth/session` | Returns `{ session, user } \| null`. |
| `POST` | `/auth/sign-out` | Returns `{ success: true }`. |

Better Auth is the underlying provider. The bearer token is opaque; treat it as a session id.

### Clubs — `clubsApi`
| Method | Path |
|---|---|
| `GET` | `/clubs` → `string[]` (flat list). |
| `GET` | `/clubs/by-league` → `Record<League, string[]>`. |

Clubs are **in-memory** in the API (`clubs.service.ts`), not a database table.

### Competitions — `competitionsApi`
| Method | Path |
|---|---|
| `GET` | `/competitions` → `ApiCompetition[]`. |
| `GET` | `/competitions/european` → `ApiCompetition[]` (Champions, Europa, Conference). |

Cached 24h in Redis on the API.

### Saves — `savesApi`
| Method | Path |
|---|---|
| `GET` | `/saves` |
| `GET` | `/saves/:saveId` |
| `POST` | `/saves` — Body `{ name, club, budget, europeanCompetitionId? }`. Creates the save **and** an initial `ClubStint` **and** `TeamSeasonStats` rows for every competition of the club's country. `balance = budget`. |
| `PATCH` | `/saves/:saveId` — Updates fields. Setting `currentSeason` cascades: creates new `TeamSeasonStats` (per competition), `PlayerSeasonStats`, and Trophy placeholders for the new season. |
| `DELETE` | `/saves/:saveId` — Cascades to all child rows. |

| `GET` | `/saves/:saveId/club-stints/current` |
| `POST` | `/saves/:saveId/club-stints` — Change club. Marks previous stint `isCurrent = false`, creates new active stint. |
| `PATCH` | `/saves/:saveId/club-stints/:stintId` |

### Players — `playersApi`
| Method | Path |
|---|---|
| `GET` | `/saves/:saveId/players?active&loaned&season` |
| `GET` | `/saves/:saveId/players/:playerId` |
| `POST` | `/saves/:saveId/players` |
| `PUT` | `/saves/:saveId/players/:playerId` |
| `PATCH` | `/saves/:saveId/players/:playerId/stats` — partial update of current-season stats. |
| `DELETE` | `/saves/:saveId/players/:playerId/release` |
| `POST` | `/saves/:saveId/players/import-fc26` — Imports the player's saved FC26 dataset into the active squad. Returns `{ imported, skipped, total }`. |

### FC26 Players Dataset — `fc26PlayersApi`
| Method | Path |
|---|---|
| `GET` | `/fc26-players?<filters>` → `{ players, total, limit, offset }`. Supports a large set of `min*`/`max*` numeric filters (ovr, pace, passing, etc.), positional filters, traits, nation, league, club, foot, sort, pagination, and `objective` for fit-score computation. |
| `GET` | `/fc26-players/filters` → metadata for filter UIs (positions, nations, leagues, clubsByLeague). |
| `GET` | `/fc26-players/:sofifaId` → full player profile. |

Numeric filter keys are computed: `min${Capitalize<Base>}` / `max${Capitalize<Base>}`. The list of bases is in `FC26_NUMERIC_FILTER_BASES` (47 attributes).

### Scout Playbooks — `playbooksApi`
| Method | Path |
|---|---|
| `GET` | `/scout/playbooks?saveId` → `{ defaultPlaybook, playbooks }`. |

| `POST` | `/scout/playbooks` |

### Chat (Mister assistant) — `chatApi`
| Method | Path |
|---|---|
| `POST` | `/chat/messages` — Body `{ message, previousResponseId? }`. Returns `{ reply, responseId }`. |

Uses OpenAI Responses API with the **API's MCP server** registered as a tool source. The `responseId` is opaque — pass it back as `previousResponseId` to continue the conversation.

### Additional API features (not yet consumed by frontend client)
The following API routes exist but have no dedicated client surface yet (`shared/api/client.ts` does not expose them):
- `saved-searches` (`/saved-searches/...`) — persistent scout filter sets.
- `shortlist` (`/shortlist/...`) — shortlisted FC26 players per save.
- `scouting` (`/scouting/...`) — squad analysis, target lists, signing evaluation.

These are surfaced indirectly through `useFc26Players` and `useJuniorChat`. If you build dedicated UIs, add the corresponding `xxxApi` objects under `shared/api/client.ts` first.

## MCP Integration

The API mounts an MCP (Model Context Protocol) server at `/mcp` (see `docs/career-hub-api/src/mcp/`). It exposes career data as tools (squad, transfers, stats, trophies) consumable by the OpenAI Responses API.

- The chat endpoint sets up the MCP tool with the user's session token forwarded as `Authorization: Bearer`.
- `require_approval: 'never'` — tool calls run without confirmation, since they are read-only for the authenticated user's own data.
- The frontend never talks to `/mcp` directly. It only calls `/chat/messages`.

## Auth Storage

`AuthProvider` ([`src/features/auth/model/AuthContext.tsx`](../../src/features/auth/model/AuthContext.tsx)) hydrates from localStorage:
- `session_token` — opaque bearer token.
- `user` — cached `ApiUser` JSON (used to render UI immediately while `getSession` refreshes in background).
- `active-save:<userId>` — last-selected save id (cleared on sign-out).

Helpers in [`src/features/auth/lib/auth-storage.ts`](../../src/features/auth/lib/auth-storage.ts) own all reads/writes. Never touch `localStorage` for auth state from elsewhere.

## Environment Variables (frontend)

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_API_URL` | Override API base URL. |
| `VITE_API_URL` | Fallback API base URL. |

The `NEXT_PUBLIC_` prefix is a legacy holdover (likely from a Next.js scaffold) — both work.

## Rate Limits

- The API uses Better Auth's rate limiter and per-endpoint limits.
- 429 responses include `Retry-After` (seconds). The client surfaces this on `ApiError.retryAfter`.
- For load testing, the API supports `DISABLE_RATE_LIMIT=true` env var server-side. Never set this in real production traffic.

## Caching (backend, but relevant to frontend behavior)

The API caches list and detail endpoints in Redis with per-service TTLs (e.g., `savesList: 15min`, `save: 30min`). The frontend's React Query cache sits on top:
- Stale-while-revalidate happens client-side (React Query defaults).
- The API invalidates its Redis cache on writes; the frontend invalidates its query keys.
- If you see stale data, check both layers.
