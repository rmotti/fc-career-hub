# 3.3 API and Integrations

## Overview

The frontend talks to a single backend: **fc26-career-hub-api** (Fastify + Prisma + Postgres + Redis), mirrored under [`docs/career-hub-api/`](../career-hub-api/) for reference. The HTTP surface is fully captured by the typed objects under `src/shared/api/` — a shared `http.ts` core plus one `modules/<domain>.ts` per resource, all re-exported through the [`client.ts`](../../src/shared/api/client.ts) barrel (the canonical import path).

Production OpenAPI docs (Swagger UI) are served by the API at `<api-base>/docs`. Use them as the live source of truth for request/response shapes when in doubt.

## Transport

### Base URL
Resolved in `shared/api/http.ts`:

1. `import.meta.env.VITE_API_URL` if set.
2. Else falls back to the default Railway host (`https://ample-love-production.up.railway.app`) and logs a warning (outside test mode).
3. `/api` is appended if missing.

### Headers & credentials
- `Content-Type: application/json`.
- Every request is sent with `credentials: "include"` so the httpOnly session cookie rides along (no `Authorization` header from the browser).
- On mutating methods, a double-submit `X-CSRF-Token` header is added from the in-memory CSRF token (lazily fetched via `GET /auth/csrf` when absent). `/auth/sign-in` and `/auth/sign-up` are CSRF-exempt.

### Status handling
- `204` → resolves with `undefined`.
- `401` (on any path other than `/auth/sign-in`, `/auth/sign-up`) → calls `unauthorizedHandler()` which clears the session.
- `429` → captures `Retry-After` header into `ApiError.retryAfter`.
- Other non-OK → throws `ApiError`.

### Error contract
Backend responses on failure follow one of two shapes:

```json
{ "error": "Erro interno do servidor.", "statusCode": 500 }
{ "error": "SHIRT_NUMBER_CONFLICT", "message": "Camisa 10 já está em uso", "statusCode": 409 }
```

The frontend `ApiError` carries `{ message, status, data, isNetworkError, retryAfter }`. Use `extractErrorMessage(err)` from `shared/api/client.ts` to compute the user-facing string — it knows about specific codes like `SHIRT_NUMBER_CONFLICT`.

## Endpoints

All endpoints below are prefixed with `/api`. Auth endpoints are public; everything else requires a valid session token.

### Auth — `authApi`
| Method | Path | Notes |
|---|---|---|
| `POST` | `/auth/sign-up/email` | Body `{ name, email, password, plan? }`. Returns `{ csrfToken, user }`; sets the session cookie. |
| `POST` | `/auth/sign-in/email` | Body `{ email, password }`. Returns `{ csrfToken, user }`; sets the session cookie. |
| `GET` | `/auth/session` | Returns `{ session, user } \| null` (401 → `null`). |
| `GET` | `/auth/csrf` | Returns `{ csrfToken }`. Used to lazily re-seed the in-memory CSRF token after a reload. |
| `POST` | `/auth/sign-out` | Returns `{ success: true }`; clears the session cookie. |

Better Auth is the underlying provider. The session is delivered as an httpOnly cookie (opaque session id); the SPA never reads it. Writes are protected by the double-submit CSRF token returned on sign-in/up.

### FC26 Players Dataset — `fc26PlayersApi`
| Method | Path |
|---|---|
| `GET` | `/fc26-players?<filters>` → `{ players, total, limit, offset }`. Supports a large set of `min*`/`max*` numeric filters (ovr, pace, passing, etc.), positional filters, traits, nation, league, club, foot, sort, pagination, and `objective` for fit-score computation. |

| `GET` | `/fc26-players/:sofifaId` → full player profile. |

### Shortlist — `shortlistApi`
| Method | Path |
|---|---|
| `GET` | `/saves/:saveId/shortlist` → `{ items }`. Each item embeds an `fc26Player` subset. |
| `POST` | `/saves/:saveId/shortlist` — Body `{ fc26PlayerId, notes?, priority? }`. 201, returns the bare item. |

| `DELETE` | `/saves/:saveId/shortlist/:itemId` — 204. |

### Scouting — `scoutingApi`
| Method | Path |
|---|---|
| `GET` | `/scouting/saves/:saveId/gaps?formation=4-3-3\|4-2-3-1` → `{ gaps }` — squad gaps for the active club. |

The shortlist UI is `localStorage`-only and not yet migrated onto `shortlistApi`.

## MCP Integration

The API mounts an MCP (Model Context Protocol) server at `/mcp` (see `docs/career-hub-api/src/mcp/`). It exposes career data as tools (squad, transfers, stats, trophies) consumable by the OpenAI Responses API.

- The chat endpoint sets up the MCP tool with the user's session token forwarded as `Authorization: Bearer`.
- `require_approval: 'never'` — tool calls run without confirmation, since they are read-only for the authenticated user's own data.
- The frontend never talks to `/mcp` directly. It only calls `/chat/messages`.

## Auth Storage

The session token itself is **not** in localStorage — it's an httpOnly cookie set by the API. `AuthProvider` ([`src/features/auth/model/AuthContext.tsx`](../../src/features/auth/model/AuthContext.tsx)) only caches non-secret hydration state in localStorage:
- `session_user` — cached `ApiUser` JSON (used to render UI immediately while `getSession` validates the cookie in background).
- `active-save-id:<userId>` — last-selected save id (cleared on sign-out).
- The CSRF token is held **in memory** (not persisted); `purgeLegacySessionToken()` strips any pre-cutover `session_token` left over from before the cookie migration.

Helpers in [`src/features/auth/lib/auth-storage.ts`](../../src/features/auth/lib/auth-storage.ts) own all reads/writes. Never touch `localStorage` for auth state from elsewhere.

## Rate Limits

- The API uses Better Auth's rate limiter and per-endpoint limits.
- 429 responses include `Retry-After` (seconds). The client surfaces this on `ApiError.retryAfter`.
- For load testing, the API supports `DISABLE_RATE_LIMIT=true` env var server-side. Never set this in real production traffic.

## Caching (backend, but relevant to frontend behavior)

The API caches list and detail endpoints in Redis with per-service TTLs (e.g., `savesList: 15min`, `save: 30min`). The frontend's React Query cache sits on top:
- Stale-while-revalidate happens client-side (React Query defaults).
- The API invalidates its Redis cache on writes; the frontend invalidates its query keys.
- If you see stale data, check both layers.
