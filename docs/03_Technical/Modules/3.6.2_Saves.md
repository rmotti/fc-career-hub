# 3.6.2 Saves and Careers

## Responsibility

A "save" is one Career Mode career. This module owns save listing, creation, selection, season advancement, and deletion. It is the root context for almost every other module — most queries are keyed by `saveId`.

## Internal Architecture

```
features/saves/
├── model/
│   └── useSaves.ts                       useSaves, useSave, useCreateSave, useUpdateSave, useDeleteSave
├── ui/
│   └── SaveSelect.tsx                    landing screen post-login to pick / create a save
└── index.ts
```

The selected save id is persisted in localStorage as `active-save-id:<userId>` (managed by `features/auth/lib/auth-storage.ts`).

## Dependencies

- [`shared/api/client.ts`](../../../src/shared/api/client.ts) — `savesApi`, `ApiSave`.
- `features/auth/lib/auth-storage.ts` — active save id storage.
- `features/new-season/ui/NewSeasonModal.tsx` — calls `useUpdateSave` to advance season.
- All hub pages — read `useSave(saveId)` and pass `saveId` to their feature hooks.

## Data Flow

### Creation
1. User on `/app` (Index page) submits the create-save form.
2. `useCreateSave().mutateAsync({ name, club, budget, europeanCompetitionId? })`.
3. API creates: `Save`, initial `ClubStint` (isCurrent=true), and `TeamSeasonStats` rows for every competition tied to the club's country. Sets `balance = budget`.
4. On success → invalidate `["saves"]`. Active save id stored locally.

### Selection
- `SaveSelect.tsx` lists saves via `useSaves()`. Clicking a save sets the active id and navigates to `/dashboard`.

### Season advance
1. Triggered by `NewSeasonModal` (mounted in `HubLayout`).
2. `useUpdateSave().mutate({ saveId, data: { currentYear, currentSeason, ... } })`.
3. API cascades:
   - Creates new `TeamSeasonStats` (per competition) for the new season.
   - Creates `PlayerSeasonStats` rows for each active player.
   - Creates trophy placeholders.
4. `onSuccess` invalidates `["saves"]`, `["saves", saveId]`, `["teamStats", saveId]`, `["players", saveId]`, `["trophies", saveId]`. This is the canonical cross-domain invalidation pattern in the codebase.

### Deletion
- `useDeleteSave()` → DELETE `/api/saves/:id`. Server cascades (`onDelete: Cascade`) to club stints, players, transfers, trophies, stats, playbooks, shortlist items, saved searches.
- Invalidates `["saves"]`.

## Local Domain Rules

1. A save is owned by exactly one user (`Save.userId`); the API filters by `userId` server-side.
2. A save always has at least one `ClubStint` — the initial one is created with the save.
3. `currentClubStint` is the stint where `isCurrent = true`. There is exactly one per save at any time.
4. Budget and balance are stored as floats in **millions of €**. `balance` is initialized equal to `budget` at creation.
5. `currentSeason` is a string in the form `"2026/27"`. Advancing it triggers server-side cascade — never set it directly on the client without going through `useUpdateSave`.
6. Deleting a save deletes everything under it. There is no soft-delete.

## Extension Points

- Save export/import (JSON download/upload) for backup.
- Save duplication (clone career to a new id).
- Multi-user shared saves — would require collaborator model on the API.
- Save thumbnails / club crests in `SaveSelect`.
