# 3.6.8 Change Club and New Season

## Responsibility

Two lifecycle actions on a save:

- **Change Club** — close the current club stint and start a new one at a different club.
- **New Season** — advance `currentYear` / `currentSeason` on the save, triggering the server-side cascade that creates next-season stats and trophy placeholders.

Grouped together because both are calendar-shaping actions invoked from the sidebar, both reset large portions of cached data, and both lean on the same `useUpdateSave` pattern.

## Internal Architecture

```

├── model/
│   ├── useClubs.ts                       reads /api/clubs and /api/clubs/by-league
│   └── useCompetitions.ts                reads /api/competitions/european
├── ui/
│   └── ChangeClubScreen.tsx              club picker with league filter, confirmation flow
└── index.ts

features/new-season/
├── ui/
│   └── NewSeasonModal.tsx                modal launched from sidebar; commits via useUpdateSave
└── index.ts
```

## Dependencies

- [`shared/api/client.ts`](../../../src/shared/api/client.ts) — `clubsApi`, `competitionsApi`, `clubStintsApi`, `savesApi`.
- [`features/saves/model/useSaves`](../../../src/features/saves/model/useSaves.ts) — used by `NewSeasonModal` for `useUpdateSave`.
- `react-hook-form` + `zod` — Change Club confirmation form.

## Data Flow

### Change club
1. User opens `/change-club` (linked from sidebar).
2. `useClubs()` populates the picker (grouped by league via `clubsApi.byLeague`).
3. User selects the next club and optionally a European competition (`useCompetitions().european`).
4. Submit → `clubStintsApi.changeClub(saveId, { club })`. Server closes the previous stint (`endYear`, `isCurrent = false`) and creates a new active stint.
5. The screen invalidates everything tied to the save (stints, players, team stats, transfers, trophies) — same pattern as season advance.

### New season
1. User clicks **Nova Temporada** in the sidebar.
2. `NewSeasonModal` opens with the proposed next season string (e.g., current `2026/27` → next `2027/28`).
3. Submit → `useUpdateSave({ saveId, data: { currentYear, currentSeason, ... } })`.
4. API cascade:
   - Creates new `TeamSeasonStats` rows per competition.
   - Creates `PlayerSeasonStats` rows for every active player.
   - Increments player ages where applicable (handled server-side).
   - Creates trophy placeholders.
5. `onSuccess` triggers the canonical cross-domain invalidation: `["saves"]`, `["saves", saveId]`, `["teamStats", saveId]`, `["players", saveId]`, `["trophies", saveId]`.

## Local Domain Rules

1. A save always has exactly one stint with `isCurrent = true`. The change-club flow guarantees this atomically.
2. Season string format: `"YYYY/YY"` (e.g., `2026/27`). The frontend never advances this without going through `useUpdateSave`.
3. The European competition selection persists on `Save.europeanCompetitionId`. Setting it to `null` removes European participation for the upcoming season's stats.
4. Advancing the season is irreversible from the UI — no "undo last season" action exists.

## Extension Points

- "Undo last season" (would require a soft history and a complex server-side rewind).
- Save snapshots before each season advance (export/import JSON).
- Coach offers / approaches mini-game before allowing club change.
- Per-season pre-flight checklist (e.g., warn if any active player has no contract info).
