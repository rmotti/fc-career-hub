# 3.6.5 Transfers

## Responsibility

Registers transfers (incoming and outgoing) and loans for a save. Each transfer updates the save's balance server-side and can auto-create or link to a `Player` row.

## Internal Architecture

```
features/transfers/
├── model/
│   └── useTransfers.ts                   useTransfers, useCreateTransfer, useUpdateTransfer, useDeleteTransfer
├── ui/
│   ├── TransfersScreen.tsx               table + filters by season/type
│   └── TransferModal.tsx                 create/edit dialog (manual form state, not RHF)
└── index.ts
```

## Data Flow

### Listing
- `useTransfers(saveId, season?)` → `["transfers", saveId, { season }]`.
- `season: "current"` filters to active-season transfers; absent returns all.

### Create
1. `TransferModal` collects `playerName`, `type`, `from`, `to`, `season`, optional `fee`, optional `playerId`.
2. `useCreateTransfer().mutate(...)` → server may auto-create a `Player` row (for incoming transfers) and returns `{ transfer, playerId, save }`.
3. `onSuccess`:
   - Invalidates `["transfers", saveId]` and `["players", saveId]`.
   - Patches the cached save with the new balance via `qc.setQueryData(["saves", saveId], …)`.
   - Also invalidates `["saves"]` and `["saves", saveId]` to be safe.

### Update / Delete
- Standard mutations. Both refresh transfers and the save (balance can change).

## Local Domain Rules

1. Transfer type is one of: `compra`, `venda`, `emprestimo_entrada`, `emprestimo_saida`.
2. `fee` is in millions of €; loans typically have `fee = 0` or null.
3. `playerId` is optional on creation:
   - **Incoming** (`compra`, `emprestimo_entrada`): server may create a new `Player` row and return its id.
   - **Outgoing** (`venda`, `emprestimo_saida`): expected to match an existing player; the server links and updates that player's status.
4. The save's balance is updated server-side as part of the transaction — the client reflects the new value from the returned `save`.

## Extension Points

- Window-based grouping (summer / winter window views).
- Per-player transfer history page.
- Cumulative spend / income summary per season.
- Auto-import transfers from a CSV.
