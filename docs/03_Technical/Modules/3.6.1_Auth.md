# 3.6.1 Auth

## Responsibility

Owns the user session lifecycle: sign-up, sign-in, sign-out, session hydration from storage, and global 401 handling. All other features depend on `useAuth()` to know who the current user is.

## Internal Architecture

## Dependencies

- [`shared/api/client.ts`](../../../src/shared/api/client.ts) — `authApi`, `registerUnauthorizedHandler`, `ApiUser`, `ApiSession`.
- `@tanstack/react-query` — clears the cache on sign-out.
- `react-router-dom` — guards redirect via `<Navigate />`.
- `localStorage` — keys: `session_token`, `user`, `active-save:<userId>`.

## Data Flow

### Bootstrap
1. `AuthProvider` mounts inside `Providers`.
2. `hydrateSession()` reads `session_token`; if missing, `isLoading = false` and the user stays unauthenticated.
3. If present: optimistically rehydrate `user` from `localStorage.user`, then call `authApi.getSession()` to validate.
4. On success → `setUser/setSession`.
5. On failure (any throw) → `clearSession()` → empties localStorage, resets state, calls `queryClient.clear()`.

### Sign-in / Sign-up
1. `authApi.signIn` or `authApi.signUp` returns `{ token, user }`.
2. Token is persisted to `localStorage["session_token"]` via `setStoredToken`.
3. A follow-up `authApi.getSession()` is called to populate the `session` object (best-effort; failure is swallowed).

### Sign-out
1. `authApi.signOut()` is invoked (failure tolerated).
2. `clearSession()` runs regardless — local state is the source of truth for "signed out".

### Global 401 handler
- `shared/api/client.ts` exposes `registerUnauthorizedHandler(fn)`.
- `AuthProvider` registers `clearSession` on mount, unregisters on unmount.
- Any HTTP 401 on a non-`/auth/sign-*` path triggers `clearSession` → user lands on `/unauthorized` on next protected-route render.

## Guards

| Guard | Behavior |
|---|---|
| `ProtectedRoute` | Loader while hydrating → if not authenticated, redirect to `/unauthorized` with `state.from`. |
| `PublicOnlyRoute` | Loader while hydrating → if authenticated, redirect to `/app`. |
| `PlanRoute` | Loader while hydrating → if `user.plan` not in `allowedPlans`, redirect to `/pricing`. Forwards outlet context. |

## Local Domain Rules

1. The token, the user object, and the active-save id are the only authentication-related items in localStorage.
2. Sign-out clears all three (the active-save id is cleared even if `authApi.signOut` fails).
3. A successful 401 on `/auth/sign-in` or `/auth/sign-up` does **not** clear the session — these endpoints intentionally return 401 for bad credentials and must not nuke an existing session.

## Extension Points

- Add `useRequireAuth(role)` for granular role checks if `ApiUser.role` ever splits beyond `ADMIN | USER`.
- Add a refresh-token path if Better Auth gains rotating tokens.
- Add OAuth providers via `authApi` (Better Auth supports them server-side).
